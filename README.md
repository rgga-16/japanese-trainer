# jlpt-n4-trainer

A JLPT N4 grammar study app: lessons, exercises, spaced-repetition reviews, conjugation drills, and timed mock tests. Fully offline — no backend, no external APIs, no CDNs. Progress is saved to `localStorage` on your device.

Runs three ways from one codebase: in the browser, as an installable PWA (Add to Home Screen), and as a native Android/iOS app via Capacitor.

## Features

- **Lessons** covering N5/N4 grammar points, each with explanations and worked examples
- **Exercises** in four formats: translation, cloze, multiple choice, and sentence ordering (文の組み立て)
- **Spaced repetition reviews** using a Leitner-system scheduler
- **Conjugation drills** for verb/adjective forms in scope for N4
- **Timed mock tests** built from mixed passages and exercises
- **Progress dashboard** tracking mastery across grammar points
- Furigana rendering throughout (kanji + reading notation, e.g. `食[た]べる`)

## Tech stack

React + TypeScript (strict) + Vite, with hash-based routing (`react-router-dom`). No backend — all content is static TypeScript compiled into the bundle, and progress persists to a single versioned `localStorage` key. Mobile packaging is Capacitor; the PWA service worker and manifest come from `vite-plugin-pwa`.

## Getting started

```bash
npm install
npm run dev
```

Then open the printed local URL in your browser.

## Scripts

| Command | Description |
| --- | --- |
| `npm run dev` | Start the Vite dev server |
| `npm run build` | Type-check and build the **web/PWA** bundle (service worker + manifest) |
| `npm run build:native` | Type-check and build the **Capacitor** bundle (relative paths, no service worker) |
| `npm run preview` | Preview the production build locally |
| `npm run sync` | `build:native` + `cap sync` — refresh the native projects |
| `npm run android` | `sync` + open the project in Android Studio |
| `npm run ios` | `sync` + open the project in Xcode (macOS only) |
| `npm test` | Run the Vitest test suite (engine + content validation) |
| `npm run test:watch` | Run tests in watch mode |
| `npm run lint` | Biome lint (`src/`) |

Biome is a local devDependency here with its own `biome.json` scoped to `src/`. Run `npm run lint` from **inside this directory**, not the workspace root. The repo is lint-clean but deliberately not format-clean — do not run `biome format` or `biome check` across it.

## Mobile

Two build targets share one `vite.config.ts`:

- `npm run build` → web/PWA. Base defaults to `/`; override with `VITE_BASE` for subpath hosting (e.g. `VITE_BASE=/japanese-trainer/ npm run build` for GitHub Pages). Emits `sw.js` + `manifest.webmanifest` so the site installs and works offline. Full guide: [docs/BUILD_WEB.md](docs/BUILD_WEB.md).
- `npm run build:native` → Capacitor. Relative asset paths for the WebView origin, and **no** service worker (the assets are already on-device; a SW there only causes cache staleness across app updates).

`dist/` is shared by both targets, so always run the right build before `cap sync` — never `cap sync` after a plain `npm run build`, or a service worker ships into the WebView.

### Android

Needs Android Studio + **JDK 21** (`android/app/capacitor.build.gradle` pins `VERSION_21`) and SDK Platform 36. `npm ci`, then `npm run android`, then Run. The debug APK can be sideloaded directly.

Release builds need a signing keystore, which this repo does not ship — [docs/BUILD_ANDROID.md](docs/BUILD_ANDROID.md) covers setup from zero, keystore generation, the `signingConfigs` patch, AAB builds, and Play Store submission.

### iOS

`npm run sync` works anywhere, but **compiling and signing require macOS + Xcode**. Capacitor 8 uses Swift Package Manager — you open `ios/App/App.xcodeproj` directly; there is no `Podfile` and no workspace.

[docs/BUILD_IOS.md](docs/BUILD_IOS.md) covers all three routes from Windows (a borrowed Mac, GitHub Actions `macos-latest` with copy-pasteable workflows, or a rented cloud Mac), plus signing, TestFlight, and the one blocker to know about: `ios/App/CapApp-SPM/Package.swift` is generated with Windows backslash paths that SPM can't resolve, so it must be regenerated by running `npm run sync` on the macOS host.

### Regenerating icons

`resources/icon.svg` (full square artwork) and `resources/icon-foreground.svg` (logo only, inside the adaptive-icon safe zone) are the sources of truth. Rasterise them to `resources/icon.png`, `icon-foreground.png`, `icon-background.png`, `splash.png` and `splash-dark.png`, then:

```bash
npx @capacitor/assets@3 generate --ios --android \
  --iconBackgroundColor '#10141c' --splashBackgroundColor '#10141c'
```

The generator is intentionally *not* a devDependency — it pulls ~300 packages and is only needed when the artwork changes. The PWA icons in `public/` (`pwa-*.png`, `apple-touch-icon-180x180.png`, `favicon.svg`) are generated from the same sources.

## Project structure

```
src/
  content/    # Static grammar/vocab/template/mock-passage data (types.ts defines the schema)
  engine/     # Pure logic: conjugator, grader, generator, SRS scheduler, furigana parsing
  state/      # localStorage persistence, app context, derived stats
  components/ # Shared UI, including per-format exercise components
  views/      # Route-level pages (dashboard, lesson browser, sessions, mock test, settings)
public/       # PWA icons + favicon, copied verbatim into the build
resources/    # Icon/splash source artwork for the native asset generator
android/      # Capacitor Android project (generated by `cap add android`)
ios/          # Capacitor iOS project (generated by `cap add ios`)
docs/         # Build guides: BUILD_ANDROID.md, BUILD_IOS.md, BUILD_WEB.md
```

`android/` and `ios/` are generated but meant to be committed — they carry hand-editable config (signing, `Info.plist`, icons). Commit them before building on another machine.

## Content authoring

Grammar content follows a strict schema (`src/content/types.ts`): each point needs an id (`n5.<slug>` / `n4.<slug>`), a lesson, at least three examples, and bank exercises. `content.test.ts` validates every content change against this schema. See [CONTENT_GUIDE.md](CONTENT_GUIDE.md) before authoring new grammar batches.
